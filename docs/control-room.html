ATL/Web Control Plane
GitHub ↗
BROWSER-NATIVE INTERFACE

Run the work.
Keep the gates.

The ATL Control Plane is the local browser interface for an owner who wants to shape work, inspect its evidence, and explicitly authorize bounded execution. It is the primary interface; atl tui remains a terminal compatibility surface.

Open the Control Plane ↗See the workflow ↓
01 · GET STARTED

Start a local browser session.

Run ATL from the project it manages. The browser server binds to 127.0.0.1; project state and provider settings stay local. Opening the page does not start an agent run.

PowerShell
cd path\to\your-project
atl init
atl ui

# Explicit alias and optional local port
atl control-plane --port 4187

On Windows, if a PowerShell execution policy blocks atl.ps1, run & "$env:USERPROFILE\.atl\atl.cmd" ui. You should see the Control Plane in your default browser. Use the local URL printed by ATL; do not treat it as a hosted dashboard.

Expected resultThe browser shows the workspace navigation and a snapshot of your project. No provider call, token use, or task execution occurs until you preview and explicitly confirm a run.
02 · THE WORKFLOW

Preview is information. Confirmation is authority.

The Control Plane deliberately separates selecting work from running it. The workflow below is the stable mental model for the browser UI and its CLI equivalents.

DraftDescribe or import workCreate a candidate without inventing a task schema.
ReviewMake success observableCheck objective, acceptance checks, risk, route, and resources.
QueueChoose what may runQueue membership is persisted and auditable.
PreviewInspect the planObserve providers, budgets, blockers, and containment before execution.
ConfirmStart one bounded runOnly an explicit confirmation starts provider sessions.
03 · BROWSER SPACES

Use each space for one decision.

Like a component manual, the Control Plane presents focused surfaces instead of hiding all actions in a single terminal. The labels can evolve, but the following jobs are backed by the current Control Plane API and state model.

OverviewRead portfolio state, blockers, activity, and the next owner decision.
TasksCreate, inspect, edit, approve, resolve, and attach resources to bounded work.
Plan StudioDraft and review a plan before it becomes queued work; planning does not dispatch a provider.
QueuesCreate/select queues and understand the ordered work a run will consider.
Team & activityRead role contracts, state decisions, narrated feed items, and session progress.
UsageView locally recorded usage. Remote provider capacity remains unknown unless a supported provider adapter reports it.
Settings / providersInspect built-in and API-provider readiness, select models, and change project or role routing.
Private by defaultThe Control Plane listens on loopback, not a public network interface. Browser content reflects the project state under your current working directory; do not share screenshots or exports containing sensitive task data.
04 · CREATE, REVIEW, AND QUEUE

Turn a plain-language request into a bounded packet.

Use New task to write the outcome in ordinary language or import a candidate from the configured inbox/source. Review the generated packet before approval: it must have an objective and at least one completion check. Attach local files or URLs only when they help the assigned worker verify the task.

  1. Draft or import. Create work from the browser instead of editing manager state by hand.
  2. Review the packet. Confirm the objective, checks, priority, risk, route, and resources match the work you authorize.
  3. Approve or resolve. Approval is a recorded owner action. For blocked work, record the missing input or completed recovery before reopening it.
  4. Add it to a queue. Selecting a task does not grant execution permission; queue membership is the persisted decision.
CLI equivalents
atl compose --title "Fix the login redirect" --check "signed-in user lands on /dashboard"
atl show
atl triage T-001
atl approve T-001 --note "Acceptance checks reviewed"
atl queue add T-001
05 · PROVIDERS AND CODEX

Use your ChatGPT-signed-in Codex without an API key.

codex is a built-in ATL worker, not an API-provider profile. Sign the Codex CLI into the same ChatGPT account you use for Codex, then verify it before previewing a queue. Do not run atl provider add codex and do not paste a fake API key.

Codex subscription setup
codex login
codex login status
atl providers
atl launch --dry-run

Use the Providers space to see whether ATL can find the executable and whether its subscription sign-in is ready. API provider profiles are different: they are stored once per machine in ~/.atl/providers.json, masked in views, and selected as a project default or a role override.

API provider example — only when you actually have a provider key
atl provider templates
atl provider add zai --key <your-api-key> --model glm-5.3
atl provider use zai --role rowan
atl launch --dry-run
Credential boundarySubscription sign-in and API billing are different paths. Built-in Codex uses its CLI login; an external API provider uses its own key. Keep keys out of repositories, task text, screenshots, and shell history.
06 · PREVIEW, CONFIRM, STOP

Read the plan before a provider receives a prompt.

Open the run preview for a selected queue. Check every listed task, role, provider, model, workspace, budget, and blocker. A preview with a missing executable or unready login is a useful result: fix the setup, then preview again. Do not bypass it.

CLI execution boundary
# Read-only execution plan
atl launch --dry-run

# Starts only after this explicit flag
atl launch --confirm --max-minutes 120 --max-sessions 5

While a run is active, the browser reports progress and offers a safe stop request. A stop ends the current bounded run; it does not mark unfinished work successful or remove its gate. Use the resulting evidence and blocker state to decide the next action.

RecoveryUse the task’s recorded blocker and the owner-action path. atl why shows the full reason and exact next command; atl approve T-001 records an owner approval only when that is the real missing gate.
