TERMINAL CONTROL ROOM

From idea
to bounded run.

The terminal is the manager's room: write or import work, inspect the ATL packet, choose execution explicitly, and watch the evidence trail.

01 · THE PICTURE

One screen for the state, one gate for the run.

The control room is readable in a static snapshot and navigable in a real TTY. The colored panels are a projection of .trust/manager/state.json, feed.jsonl, the persistent queue, and provider session logs.

02 · COMPOSE OR IMPORT

Start with what you mean, not the task schema.

Press c in atl ui. Choose the outcome and surface, describe the work naturally, and press Ctrl+S. ATL then shows a recommended packet with the title, objective hint, checks, route, worker, priority, risk, and resources. Nothing is persisted until you press Enter on that preview.

01ShapeOutcome + surface
02DescribePlain-language draft
03PreviewRoute + packet
04CreateHuman confirmation

Need existing work? Press i and choose the read-only file inbox, GitHub issues, or Azure Boards adapter. Markdown screenshots and links in those sources become packet resources; source systems are never written back by intake. In packet review, press a to attach a URL or local file.

03 · REVIEW, QUEUE, LAUNCH

Focus is not permission to execute.

Keyboard focus only tells you what you are reading. Queue membership is a separate, persisted decision.

e / v EditSet objective, completion checks, priority, risk, and route.
u ResolveWrite what changed or what approval/input is now available; ATL records the note before reopening the task.
x QueueAdd or remove the selected task from queue.json.
Q Queue screenEvery queued task with its live gate state, role, provider, and model.
l PreviewSee role, provider, workspace, auth, budget, and blockers.
Enter / y RunConfirm the bounded queue run inside the control room.
L LogsOne stream of state decisions (⚙) and team narration; follows the latest entry, works mid-run.
Run is always gated.The confirmation screen is explicit; execution is sequential, bounded, and containment-blocks a missing or stalled provider. A blocked task is recoverable: press u, write the resolution, then x, l, and Enter. Stale project workspaces are archived and rebuilt from the current checkout snapshot. While a confirmed run is active, the run screen shows per-task queue progress and the active session-log tail; the room re-reads state and feed every ~2 seconds (1s during a run) and the header shows the sync age.
04 · PROVIDER REGISTRY

Connect Codex, Claude, GLM, or your own local CLI.

ATL roles and model providers are separate. Pip, Mira, Rowan, Sage, and Beacon are role contracts. A provider is the executable that receives the role prompt. The control room shows the effective provider, model, and auth for every role. Add custom profiles under providers.catalog.

{
  "providers": {
    "default": "codex",
    "auth": "subscription",
    "model": "gpt-5.6-luna",
    "by_role": { "rowan": "glm" },
    "catalog": {
      "glm": {
        "command": "zcode",
        "model": "glm-4.6",
        "args": ["exec", "--model", "{model}", "--cwd", "{workspace}", "-"]
      }
    }
  }
}

Use the exact non-interactive flags supported by your ZCode installation. ATL expands {root}, {workspace}, {role}, {task_id}, {auth}, {model}, and {prompt}. Use "prompt_arg": "--prompt={prompt}" when ZCode expects a prompt flag; otherwise include - in args and ATL sends the prompt through stdin.

atl providers
atl provider models --provider codex
atl provider set --provider codex --model gpt-5.6-luna
atl provider set --role rowan --provider glm --model glm-4.6
atl launch --dry-run --worker codex --model gpt-5.6-luna

Verify the executable and selected model with atl providers, inspect the exact command with atl launch --dry-run, and only then confirm.
