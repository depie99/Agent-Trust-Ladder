PRACTICAL PLAYBOOKS

From messy
to moving.

These guides show how to talk to ATL, what it will return, and how to recognize a result you can trust. Start with the guide that matches your work.

01 · PROMPTING WITH ATL

You do not need to choose a skill.

Describe the problem in the language you already use with a teammate. Include the visible symptom, the desired outcome, and any constraint you know. ATL will decide whether the request needs framing, specification, planning, implementation, verification, review, or audit.

Good prompt

$atl The checkout callback works locally but fails in production. Find the real boundary, keep the existing auth contract compatible, and prove the deployed callback.

What ATL should return

  • A compact Workflow Manifest.
  • The smallest sufficient route.
  • Explicit gates and a stop condition.
  • A verdict that separates proven from inferred.
02 · VIBE CODING WITH GUARDRAILS

Let the agent move fast inside a visible loop.

Vibe coding becomes trustworthy when the agent can state what it believes, make a bounded change, run a check that can fail, and repair only within the authorized scope. The speed comes from shorter feedback loops, not from skipping the loop.

01FrameWhat does “done” mean?
02PlanWhere can it break?
03BuildWhat is the smallest change?
04VerifyWhat did we directly observe?
Do not confuse speed with autonomy.Autonomy is earned per task class, after evidence shows the agent can handle that class safely.
03 · DOCUMENTATION AS YOU BUILD

Keep docs in the same change conversation.

When a code, API, configuration, deployment, or operational change changes what engineers must know, run a documentation-impact check in the same workflow. Choose one primary reader and one outcome for each page.

Discover

Find the source of truth, navigation, existing terminology, and sync anchor.

Shape

Choose quickstart, how-to, reference, explanation, runbook, or decision record.

Write

Lead with the task, use copyable examples, and label unknowns.

Verify

Check links, examples, retrievability, freshness, and rendered instructions.

WRITING DOCS YOURSELF?

Choose the reader's need, not a document label.

Business, product, technical, operational, and learning documents can all be routed from the situation and outcome. This chooser ships with the atl-tech-docs skill — use it when you are the one authoring a page.

Recommended documentTutorial / quickstartProvide a guided learning path with a known starting point and successful result.
04 · REVIEW AND AUDIT

A finished diff is an input, not a verdict.

Use `atl-audit` when a PR, diff, or agent session already exists. Use `atl-ui-review` when the real rendered surface matters. Use `atl-verify` when implementation exists and the question is whether the evidence actually supports completion.

ImplementedFiles or behavior changed.
ObservedA real command, UI path, or runtime behavior was seen.
MeasuredA named metric or check produced a result.
UnknownThe consumer, runtime, or external boundary remains inferred.
05 · MODEL ROUTING AND REVIEW

Give each model the job it is good at.

Do not use the smartest model for every task by default. Route by capability, give the worker real tools and repository context, require a plan before implementation, and use a different model or independent context to review the result.

↗CODEBuild and debugImplementation, refactors, debugging, and fast execution.
✦JUDGMENTDecide and architectArchitecture, tradeoffs, ambiguity, and hard decisions.
◈ANALYSISRead and compareReading, comparison, synthesis, and structured reasoning.
✧IDEASExplore possibilitiesBrainstorming, exploration, and alternative approaches.
ROUTE→PLAN→BUILD→REVIEW→VERIFY→LOG
01RouteChoose the capability, not the brand.
02PlanGoal, approach, files, risks, gate.
03ReviewIndependent model or context.
04LogModel, version, evidence, outcome.
Review is not agreement.The reviewer must inspect the diff and evidence, test failure modes, and disclose when independent review was unavailable.
06 · MANAGER MODE

Manage outcomes, not agent transcripts.

You are the manager of the digital team. ATL gives each colleague a name, role, mission, status, checkpoint, and evidence trail while keeping you at the portfolio level: priorities, decisions, blockers, risk, and outcomes.

01DelegateGive a bounded mission and write set.
02CoordinateRoute context and follow-ups.
03ReviewChallenge the work independently.
04BriefGet shipped, blocked, and next.
Overnight needs a contract.Define “complete when,” allowed actions, forbidden actions, wake conditions, stop rules, and the morning report. Time alone is never a finish condition.
