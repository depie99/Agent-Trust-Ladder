PERSISTENT ENGINEERING KNOWLEDGE

The ATL Brain:
evidence that survives.

The Brain gives ATL durable project memory without turning memory into authority. It preserves sources, links claims to revisions, surfaces disagreement and staleness, and supplies bounded context to workers.

WHY IT EXISTS

Context is useful. Context is not proof.

01

Sessions end; evidence should not.

Research records, source bytes, revisions, claims, and decisions remain available after an agent restart or context compaction.

02

Interpretations can disagree.

ATL preserves both claims and marks the subject conflicted instead of overwriting one interpretation with the other.

03

Workers need bounded context.

Each launch receives only a task-scoped context pack with claim IDs, statuses, source IDs, revisions, and checked times.

AUTHORITATIVE BOUNDARY

Brain context informs work.
ATL evidence closes it.

A claim marked UNKNOWN, PARTIAL, CONFLICTED, or stale can guide investigation, but it cannot satisfy a completion check. Only an observed task evidence entry can do that.

IMPLEMENTED STORE

Small, inspectable,
rebuildable.

The current store is project-local and file-based. Writes use atomic replacement; source snapshots are content-addressed; duplicate replay is idempotent.

“.trust/manager/brain/” is the runtime home.

SOURCESObserve

Source and freshness status

See source counts, intake outcomes, raw revisions, stale claims, and explicit failures. “Unavailable” is never rendered as “unchanged.”

APPROVALSManager gate

Approve a claim

Review the source-linked claim and approve it from the browser. Conflicted claims cannot be approved until the conflict is resolved.

PROMOTIONBounded automation

Promote skills and routines

Validate a skill, require Gold evidence and fixtures, then register a routine. Routines remain disabled by default.

CLI REFERENCE

Terminal equivalents.

inspect sources and claims
atl brain status
atl brain list
atl brain stale
atl brain approve <claim-id>
govern the next level
atl brain skill validate --set id=summary --set version=1.0.0
atl brain skill promote --set id=summary --set version=1.0.0 --set gold_verified=true --set fixtures=f1
atl brain routine register --set id=daily --set skill_id=summary --set skill_version=1.0.0 --set schedule=daily --set idempotency_key=daily+source --set retry_limit=2
HONEST LIMITS

What is deliberately not automatic.

The current Brain does not send messages, deploy, spend money, change policy, or enable routines on its own. Provider quota remains unknown unless provider telemetry directly proves it. Browser context is advisory, not a security boundary.
