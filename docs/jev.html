START HERE

Choose the cheapest route that answers your question.

For a clear task, use the deterministic router. For an ambiguous task, ask Jev for one bounded routing opinion. Jev does not write code, generate documentation, or replace the worker.

CLEAR TASK

atl route T-001

Use local keyword and label routing. No Jev request.

AMBIGUOUS TASK

--smart

Ask one typed Jev choice, then require confidence.

HIGH RISK

ATL remains owner

Jev may suggest a route; it cannot approve risk or evidence.

01 · SETUP

Enable Jev only when you need it.

Jev support is already inside ATL. The package does not install the TypeSafe SDK or add a runtime dependency. After atl init, edit the project configuration and set the API key in the current shell.

config/jev.json
{
  "version": 1,
  "enabled": true,
  "model": "jev-latest",
  "min_confidence": 0.75,
  "timeout_ms": 2500
}
PowerShell
$env:TYPESAFE_API_KEY = "..."
atl route T-001 --smart
DefaultThe checked-in config is disabled. Normal intake and normal routing never call Jev.
02 · PROMPT

Write the task for ATL, not for Jev.

There is no second prompt. Give ATL the visible problem, affected surface, constraints, and observable checks. ATL builds the compact state and closed route choices.

Good ATL task
Improve the checkout page's loading state. Inspect the rendered UI, preserve the existing visual language, and verify the result at mobile and desktop widths.
Compact state sent to Jev
{
  "title": "Improve the checkout page's loading state",
  "objective": "Inspect the rendered UI and verify mobile and desktop widths.",
  "labels": ["ui"]
}
Keep authority in ATL.Do not ask Jev to approve merges, deployments, destructive actions, permissions, or evidence waivers.

04 · EXAMPLES

Give the router a useful surface.

Docs versus implementation

Update the API authentication guide because the token exchange changed. Check runtime configuration, update examples, and verify the documented command.

Likely route: atl-tech-docs.

UI versus implementation

The empty state is confusing on mobile. Inspect the rendered page, improve hierarchy and responsive behavior, then verify both widths.

Likely route: atl-ui-review.

Formal verification

The manager can reach done without all completion evidence. Model transitions, add a negative control, and verify the invariant.

Likely route: atl-formal-verification.

Content and SEO

Rewrite the pricing page for search intent without inventing product claims. Preserve facts and verify metadata and links.

Likely route: atl-content-quality.

05 · TOKEN POLICY

One small call, not another skill stack.

The `--smart` request contains only task fields and route descriptions. It does not contain the repository, skill bodies, or a request for a generated explanation.

01ExplicitNo automatic call.
02CompactTitle, objective, labels.
03TypedOne closed choice.
04FallbackLocal route wins uncertainty.

ResultJev can reduce wasted routing context. It does not reduce the tokens a worker needs to implement a large task.

06 · TRUST

Confidence is routing evidence, not completion proof.

ATL remains authoritative for scope, skill availability, permissions, status transitions, evidence requirements, review, merge, deployment, and destructive actions. The selected worker must still plan, implement, review, verify, and return the Trust Verdict.

07 · TROUBLESHOOTING

Fallback is expected behavior.

If smart routing falls back, run these checks:

Diagnostics
atl validate
atl route T-001
$env:TYPESAFE_API_KEY

Then confirm that `config/jev.json` is enabled, the key exists in the current shell, the model is available, the threshold is appropriate, and the candidate skill exists in `config/skill-routing.json`.
