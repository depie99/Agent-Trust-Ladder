CHOOSE YOUR ROUTE

Start with the problem you have.

Write your prompt →
01

My idea is still vague

ATL frames the request, names unknowns, and turns intent into observable acceptance examples.

Route: frame → specify
↗ 02

A bug crosses layers

Trace the payload from producer to persistence to the user-visible result. Keep legacy callers and failure cases visible.

Route: trace → plan → verify
↗ 03

Production or deployment is involved

Declare configuration, bundle, artifact, consumer, and runtime contracts before calling a build “done.”

Route: ledger → consumer → runtime proof
↗ 04

I already have a diff or PR

Do not restart as greenfield work. ATL audits what changed, what was actually checked, and what remains inferred.

Route: audit → trust verdict
↗ 05

I need a team of models

Route implementation, judgment, analysis, and ideation to fit-for-purpose roles, then add an independent review pass.

Route: route → plan → review → verify → log
↗ 06

I want to manage the team

Keep the portfolio view: priorities, progress, blockers, decisions, evidence, and the next move—not every agent transcript.

Route: delegate → coordinate → review → brief
↗ 07

I want the team history in Codex

Project ATL feed and provider transcripts into Codex history with a token-free projection, safe rollover, or an explicit visible turn.

Route: bridge → inspect → choose transport

DEPLOYMENT BOUNDARYCritical dose

Build passes, production does not

Use this when configuration, packaging, deployment, auth, or an external service can disagree.

›$atl Production auth was changed and the build passes, but the callback is uncertain. Create a contract ledger for source config, bundle, artifact layout, consumer, and real runtime callback. Stop at conditional validity if a boundary cannot be observed.
Expected proofbundle check · pipeline inspection · consumer observation · real callback

QUICKSTART

Bring a messy issue.
Leave with a route.

Two steps. No skill catalog to memorize.

1 · Install the front-door skill into your agent

any agent CLI
npx skills add depie99/Agent-Trust-Ladder --skill agent-trust-ladder -a claude-code -a codex

Works with 75+ agents (Claude Code, Codex, Cursor, Gemini CLI…). Restart the session after installing so the skill is discovered. Prefer the CLI and the five-bot team runtime? See the Team guide ↗.

2 · Describe the problem in plain language

your first prompt
$atl The checkout callback fails only in production. Find the real boundary and prove the deployed callback.

Paste it into any session in your project. You bring the symptom, the desired outcome, and any constraint you know — ATL chooses the route, the dose, and the gates.

01ManifestBefore real work: outcome, route, dose, gates, and stop condition.
02RouteThe smallest sufficient workflow runs — no ceremony without a named failure mode.
03EvidenceChecks that actually ran, with outputs and open unknowns.
04VerdictSix plain questions answered — including what remains inferred.
New terms“Dose” is how much process the work earns (direct · standard · critical). “Route” is the sequence of skills ATL runs. “Trust verdict” is the evidence-backed answer to “is this actually done?”. All of them are defined on the Reference page.
REFERENCE

What ATL returns at each gate.

Open all source skills ↗
MANIFEST

Before material work

Outcome, observed need, playbook, dose, route, gates, stop condition, and the context intentionally loaded.

EVIDENCE PACKET

After verification

Checks that actually ran, their outputs, skipped evidence, unresolved unknowns, and the next safe action.

TRUST VERDICT

Six plain questions

What changed, why, what could break, downstream impact, objective achieved, and which boundary contracts remain inferred.

DOSE

Spend only what matters

Direct for isolated work, standard for ordinary changes, and critical only when risk or unresolved boundaries justify it.
