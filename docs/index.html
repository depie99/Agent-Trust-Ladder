CHOOSE YOUR ROUTE

Start with the problem you have.

Write your prompt →
01

My idea is still vague

ATL frames the request, names unknowns, and turns intent into observable acceptance examples.

Route: frame → specify
↗ 02

A bug crosses layers

Trace the payload from producer to persistence to the user-visible result. Keep legacy callers and failure cases visible.

Route: trace → plan → verify
↗ 03

Production or deployment is involved

Declare configuration, bundle, artifact, consumer, and runtime contracts before calling a build “done.”

Route: ledger → consumer → runtime proof
↗ 04

I already have a diff or PR

Do not restart as greenfield work. ATL audits what changed, what was actually checked, and what remains inferred.

Route: audit → trust verdict
↗ 05

I need a team of models

Route implementation, judgment, analysis, and ideation to fit-for-purpose roles, then add an independent review pass.

Route: route → plan → review → verify → log
↗ 06

I want to manage the team

Keep the portfolio view: priorities, progress, blockers, decisions, evidence, and the next move—not every agent transcript.

Route: delegate → coordinate → review → brief

WORKED EXAMPLES

Prompts you can paste.

Each example tells ATL what success must prove.
CROSS-LAYER BUGStandard dose

Selection changes, then reverts

Use this when the UI looks correct but the state does not survive the request or refresh.

›$atl The selected seller changes in the UI but returns to the previous store after refresh. Trace the payload, route, workflow, persistence, and user-visible result. Preserve legacy input and verify the failure cases.
Expected proofnew input · legacy input · unknown entity · malformed input · persistence failure
DEPLOYMENT BOUNDARYCritical dose

Build passes, production does not

Use this when configuration, packaging, deployment, auth, or an external service can disagree.

›$atl Production auth was changed and the build passes, but the callback is uncertain. Create a contract ledger for source config, bundle, artifact layout, consumer, and real runtime callback. Stop at conditional validity if a boundary cannot be observed.
Expected proofbundle check · pipeline inspection · consumer observation · real callback
SMALL CHANGEDirect dose

One isolated UI label

Use this when there is no changed contract, persistence, deployment, or external service.

›$atl Rename the empty-state heading on the settings page. Keep the existing style and verify the rendered text.
Expected proofrendered text · focused visual check · no deployment gate
