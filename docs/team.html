THE DIGITAL TEAM

Five bots.
One state machine.

Mira, Pip, Rowan, Sage, and Beacon are persistent engineering teammates: they hold a task queue in a single state file, narrate their work to a team feed, and refuse any action outside their role contract. Install once, point them at your issues, and manage them like a real team — from any terminal or agent CLI.

5role contracts
1state file to resume from
0dependencies beyond Node 18+
Anyharness: ZCode, Codex, Claude, Grok

WHO DOES WHAT

The roster.

Each name is a strict contract, not a personality. The runner physically rejects any command that falls outside the actor's contract — that rejection is the system working. The human manager sits above Mira and may override anything with --actor manager.

🧭JUDGMENT

Mira

Coordinator / chief of staff. Assigns triaged work, unblocks stuck tasks, escalates to you, and writes the manager brief. Keeps the whole picture moving.

May not: write application code, merge, deploy, or review her own coordination.

Gateassign · unblock · brief
📥ANALYSIS

Pip

Intake and triage. Turns raw reports into bounded tasks: one objective, observable completion checks, priority, and risk. Rejects noise with a reason.

May not: implement anything or assign workers. A task leaves triage only with at least one observable check.

Gateobjective + checks
🔨CODE

Rowan

Builder. Implements, refactors, and debugs — only inside the task's isolated workspace (git worktree or clone). Records observed evidence and checkpoints progress.

May not: touch your active checkout, self-certify, or retry a third time without a new hypothesis.

Gateworkspace + evidence
🔍REVIEW

Sage

Independent reviewer. Reads the diff and the evidence packet — never just the builder's conclusion — then approves or requests changes with findings.

May not: implement fixes or approve without seeing the diff and evidence.

Gatereview verdict
🌙VERIFIER

Beacon

Verifier / night watch. Closes a task only when every completion check has passing observed evidence. Watches retry timers, stale work, and preserves run memory.

May not: build, extend budgets, or mark done from intention instead of observation.

Gatefinish conditions
SETUP

Install once, per machine.

Requires Node.js 18+ and a clone of the repository. The installer puts an atl command on your user PATH, copies the runtime to ~/.atl, and wires the role prompts into Codex CLI and Claude Code automatically.

Windows

git clone https://github.com/depie99/Agent-Trust-Ladder.git
cd Agent-Trust-Ladder
scripts\install-atl.cmd

macOS / Linux

git clone https://github.com/depie99/Agent-Trust-Ladder.git
cd Agent-Trust-Ladder
./scripts/install-atl.sh
Options--no-path skips the PATH change; ATL_HOME=<dir> relocates the install. Re-running the installer is how you update. Uninstall: delete ~/.atl, the wired atl-*.md prompt files, and drop ~/.atl from PATH.

No installer? Every command also works from a repo clone as node runtime\atl-manager.mjs <command>.

FIRST RUN

Set up any project in one minute.

STEP 1initScaffold this project: state, inbox, briefs, workspaces, and config. Never touches code.
STEP 2add workDrop markdown tasks into the inbox — or wire GitHub issues / Azure Boards in config.
STEP 3intakePull new tasks in. Duplicates are detected by source key, so re-running is safe.
STEP 4watchOpen the team feed and the brief. The bots narrate everything they do.

The four commands

cd your-project
atl init
atl intake
atl feed --roster

config/manager.json         ← intake sources, budgets, routines
config/model-routing.json   ← the roster + model policy
INTAKE

Give the team work.

Three ways in. All are deduplicated — the same task never enters the queue twice.

LOCAL FILE

Markdown inbox — works offline, zero credentials

Drop .md files into .trust/manager/inbox/. A ## heading starts a task; a Checks: list pre-fills completion checks; a plain - [ ] item line becomes a minimal task. Pip still owns triage — pre-filled checks are a head start, not a verdict.

task file
## Fix login redirect loop
@source: https://github.com/you/repo/issues/12
@priority: high
@risk: risky
Checks:
- valid session is never bounced to /login
- expired session redirects exactly once
pull it in
atl intake
#  + T-001 [new] (file) Fix login redirect loop
GITHUB

GitHub issues

Enable in config/manager.json under intake.github. Every open issue becomes a candidate task carrying its labels.

json
"github": { "enabled": true, "repos": ["owner/name"] }
Private reposUnauthenticated requests return 404 for private repositories. Run gh auth login or set a GITHUB_TOKEN with read access, then re-run intake.
AZURE BOARDS

Azure DevOps — sprint by sprint

Works with self-hosted Azure DevOps Server. The adapter queries the sprint iteration by WIQL and pulls tasks, bugs, and stories with state, type, priority, and assignee.

config/manager.json
"azure": {
  "enabled": true,
  "org_url": "https://devops.example.com/Collection",
  "project": "MyProject",
  "iteration_path": "MyProject\\Sprint 73",
  "token_env": "AZDO_PAT"
}
bash
set AZDO_PAT=<your-token>      (PowerShell: $env:AZDO_PAT="...")
atl intake --source azure
Token scopeThe token only needs Work Items: Read. Nothing in the runner writes back to your tracker — reviewing and closing still happen in Azure.
DAILY USE

Run the relay.

Work moves through fixed gates. Every stage records who acted and what they observed — the table below is the whole workflow.

StageBotYou run
New task arrivesPip triagesatl triage T-001 → update --set objective=… --check "…" → move triaged
TriagedMira routesatl assign T-001 --to rowan --actor mira
AssignedRowan buildsatl workspace T-001 → move in_progress → change code in the workspace
Checks observedRowan submitsupdate --evidence-pass "…" → move in_review
In reviewSage judgesupdate --review "approve: findings" → move verifying
VerifyingBeacon closesmove done — only when every check has passing evidence
Stuck / missing inputAnyone honestblock --reason "…" --wake-in 8h · escalate --reason "…"

Blocked work carries a retry timer that Beacon watches. Exhausted attempt budgets (default 3) escalate to you. The full state machine is on the Diagrams page ↗.

PERSISTENCE

They survive restarts.

Everything the team knows lives in .trust/manager/state.json — tasks, evidence, blockers, timers, and a full decision trail. Any session (yours, a fresh agent window, tomorrow morning) resumes from that file instead of re-deriving. Builders work in disposable per-task workspaces, so a crashed session never leaves your checkout dirty. The wake loop (atl wake) is the heartbeat: run it any time and Mira tells you exactly what should happen next — untriaged arrivals, stale checkpoints past the 24-hour budget, exhausted retries, due timers, and escalations.

PROMPTING

Instruct the bots three ways.

SLASH

Native slash commands — Codex CLI and Claude Code

The installer detects these harnesses and copies the role prompts into place: ~/.codex/prompts and ~/.claude/commands. In a session, type /atl-mira to coordinate, /atl-pip to triage, /atl-rowan to build, /atl-sage to review, /atl-beacon to verify. The prompt makes the agent load its contract first and act only through the runner. Add one line to your project's AGENTS.md / CLAUDE.md ("This project uses the ATL team: run atl wake and follow the role prompts") so every session knows the team exists.

PASTE

Paste-ready prompts — any agent, including Grok and Cursor

No slash-command support needed. Open ~/.atl/runtime/prompts/, copy the role you want (mira.md, pip.md, rowan.md, sage.md, beacon.md), and paste it as the first message of any agent session opened in your project. Same contracts, same enforcement.

HANDS-ON

Drive the team yourself — no agent required

Every command takes --actor, and the runner tells you who is allowed to do what. Try to assign as Rowan and the runner refuses and names the right role. The human manager (--actor manager) can always override. Delegate what you want; keep the gates you care about.

example
atl assign T-001 --to rowan --actor mira
ROUTINES

Routines — routing policy declared in advance

Routines are Mira's decisions written down ahead of time, applied at intake. when matches source, keyword, label, or work-item type; then sets priority, risk (risky implies independent review), and/or a pre-routed worker — the moment Pip finishes triage, the runner kicks that worker automatically.

config/manager.json
"routines": [{
  "name": "bugs-to-rowan",
  "when": { "source": "github", "label": "bug" },
  "then": { "priority": "high", "assign_to": "rowan" }
}]

atl routines lists declared policies; the feed shows each one firing.

WATCH THEM WORK

The feed, the wake, the brief.

The team chat

atl feed --roster        # roster + full transcript
atl feed --task T-001    # one task's thread

Pip announces grabs and triage verdicts; Mira announces routing ("kicking rowan."); Rowan claims with a ● Running card; Sage posts verdicts; Beacon closes with ● Done.

The manager view

atl wake                 # what should happen next
atl brief --save         # shipped · blocked · evidence · next moves
atl show                 # the portfolio at a glance

Escalations land with you. Merge, deploy, spend, external messaging, and policy always stay human decisions.

SKILLS

Use the skills inside.

The team is the runtime; ATL's skills are the methodology any agent can load — the same repo ships both, and they install separately.

INSTALL

Install the skills into your agents

The skills CLI ↗ installs into 75+ agents — Claude Code, Codex, Cursor, Gemini CLI, and more — from this same repository:

bash
npx skills add depie99/Agent-Trust-Ladder --skill agent-trust-ladder -a codex -a claude-code

Slash commands for Claude Code are also in the repo under commands/. Restart your agent session after installing so skills are discovered.

Companion skillsTwo more skills make the team's output easier to review: npx skills add humanlayer/skills --skill show-me visual-pr. When a task closes, type /show-me and the finishing bot summarizes the change as diff views and trees instead of prose; /visual-pr prepares a reviewer-friendly pull request — invoke it by name, and the manager approves before anything is published.
CATALOG

What each skill is for

atl is the front door — describe a problem and it routes to the smallest trustworthy workflow. atl-frame / atl-specify / atl-plan / atl-implement / atl-verify are the delivery ladder: bound the idea, define observable behavior, map the codebase, execute with repair loops, and prove it. atl-team is the coordination contract this runtime enforces. atl-audit judges an existing diff or session. atl-trust decides, from recorded evidence, how much autonomy a task class has earned. atl-bootstrap onboards an existing codebase honestly. Full list on the Skills page ↗.

TOGETHER

How the team and the skills compose

A bot playing Rowan can load atl-implement for its bounded repair loops; Sage reviews with atl-audit standards; Beacon's finish checks are atl-verify evidence packets; and every earned outcome feeds atl-trust, which is what lets you widen the bots' budgets over time without guessing. The runtime enforces the gates; the skills provide the craft inside them.
