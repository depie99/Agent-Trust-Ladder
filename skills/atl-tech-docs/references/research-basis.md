# Research basis

This workflow is synthesized from authoritative documentation guidance, not copied as a vendor-specific house style:

- [Google developer documentation style guide](https://developers.google.com/style/) — project-specific rules first, then a maintained style hierarchy; clarity and consistency over rigid rules.
- [Google technical writing: documents](https://developers.google.com/tech-writing/one/documents) — define audience, scope/non-scope, reader outcome, and structure.
- [Google technical writing: self-editing](https://developers.google.com/tech-writing/two/editing) — iterative editing, peer review, active voice, numbered procedures, and audience perspective.
- [Microsoft Learn style quick start](https://learn.microsoft.com/en-us/contribute/content/style-quick-start) — intent-first, everyday words, concise sentences, and scannable procedures.
- [GitHub Docs style and content model](https://docs.github.com/en/contributing/style-guide-and-content-model) — named content types and consistent article structure.
- [GitHub content design principles](https://docs.github.com/en/contributing/writing-for-github-docs/content-design-principles) — user-centered, high-impact, iterative, and “just enough” documentation.
- [Diátaxis](https://diataxis.fr/) — tutorials, how-to guides, reference, and explanation as four distinct reader needs.
- [AWS DevOps guidance on documentation lifecycle](https://docs.aws.amazon.com/wellarchitected/latest/devops-guidance/dl.eac.5-integrate-technical-and-operational-documentation-into-the-development-lifecycle.html) — version docs with code, automate generation/checks, and keep docs living with the system.
- [Vale](https://docs.vale.sh/) — markup-aware, configurable prose linting that can run locally and in CI.
- [markdownlint rules](https://github.com/markdownlint/markdownlint/blob/main/docs/RULES.md) and [lychee](https://github.com/lycheeverse/lychee) — structural Markdown and link validation options.

These sources inform the workflow's principles; local project conventions and the actual implementation remain authoritative.
