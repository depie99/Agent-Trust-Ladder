# Agent Trust Ladder — راهنمای فارسی

>[English full guide: GUIDE.md](GUIDE.md) · [English README: README.md](README.md)

یک اپراتور مهندسیِ مبتنی بر شواهد برای ایجنت‌های کدنویسی — یک اسکیل که در **هر نقطه از پروژه**، به نسبت نیازت، فقط همان بخش را اجرا می‌کند.

ایجنت‌ها اجرا را ارزان کرده‌اند؛ گلوگاه جدید **تأییدِ انسانی در مقیاس خروجی AI** است. این اسکیل هر مرحله از کار را به یک **حکم اعتماد (Trust Verdict)** با شواهد واقعی ختم می‌کند:

> **چه چیزی تغییر کرد؟ چرا؟ چه چیزی ممکن است بشکند؟ اثرش روی چه چیزهای دیگری است؟ به هدف رسیدیم؟**

---

## نصب

~~~bash
npx skills add depie99/Agent-Trust-Ladder --skill agent-trust-ladder
~~~

یا پوشهٔ `skills/agent-trust-ladder/` را در پوشهٔ اسکیل‌های ایجنت خودت کپی کن (`.claude/skills/`، `.agents/skills/`، …).

اسلش‌کامندها (اختیاری، برای Claude Code): فایل‌های `commands/*.md` را در `.claude/commands/` بگذار.

## کنترل دوز — ضد مراسمِ اضافه

| دوز | کی؟ | چی می‌گیری؟ |
|---|---|---|
| **Direct** | کارِ کوچکِ قابل‌برگشت (تایپو، متن، کامنت) | بدون آرتیفکت؛ یک خط برنامه، انجامش بده، دیف را نشان بده |
| **Standard** | فیچر یا باگ‌فیکس معمولی | بریف → اسپک سبک → پلن با تسک‌ها → خلاصهٔ شواهد (هر کدام یک صفحه) |
| **Critical** | احراز هویت، پرداخت، مایگریشن، production، چند-سرویسی | اسپک کامل + بستهٔ شواهد + گیت‌های تأیید انسانی |

## ۸ ورودی (Mode)

| کامند | برای |
|---|---|
| `/atl` | خودش تشخیص می‌دهد کجای کار هستی و همان بخش را اجرا می‌کند |
| `/atl-bootstrap` | شناخت پروژهٔ موجود: دستورهای واقعی، مرزها، قواعد واقعی (بدون اختراع) + پالیسی اعتماد اولیه |
| `/atl-frame` | ایدهٔ مبهم → بریف محدود؛ یک راند سؤال با پیشنهاد پیش‌فرض؛ تعیین دوز |
| `/atl-specify` | رفتار قابل‌مشاهده + مثال‌های پذیرش؛ تا تأیید صریح انسان جلو نمی‌رود |
| `/atl-plan` | تحلیل اثر، pre-mortem، تسک‌هایی که هرکدام دستور verify خودشان را دارند |
| `/atl-implement` | حلقهٔ خودتصحیحی با بودجهٔ تعمیر؛ هرگز تست را برای سبز شدن تضعیف نمی‌کند |
| `/atl-verify` | اجرای کوچک‌ترین مجموعهٔ راستی‌آزمایی معتبر + حکم اعتماد ۵ سؤالی |
| `/atl-audit` | «ایجنت ۵۰۰ فایل را عوض کرد — امن است؟»؛ verdict فقط-خواندنی روی دیف/PR موجود |
| `/atl-trust` | نردبان L0–L7: چه کارهایی ایجنت بتواند خودش انجام دهد؟ با گیتِ ۹ سؤالی |

## از کجا شروع کنم؟

~~~text
/atl-bootstrap                                  ← اولین بار روی هر پروژهٔ موجود
/atl-frame کاربرها فیلترهاشان گم می‌کند          ← ایدهٔ مبهم
/atl-audit PR #482                              ← بررسی یک دیف بزرگ
~~~

بدون کامند هم می‌شود: بگو *"این دیف را audit کن"* یا *"این ایده را frame کن"* — خودش مسیر درست را پیدا می‌کند.

## در پروژه‌ات چه چیزی ساخته می‌شود؟

~~~text
.trust/
  project-brief.md   # قواعد واقعی پروژه (مشابه constitution)
  trust-policy.md    # سقف استقلال ایجنت برای هر کلاس کار
  ledger.md          # دفتر ثبت: verdictها، شکست‌ها، تغییرات اعتماد
  specs/001-.../     # بریف، اسپک، پلن، شواهدِ هر تغییر
~~~

## چرا با بقیه فرق دارد؟

- **دوز، نه دگم** — کارِ کوچک اصلاً وارد مراسم نمی‌شود.
- **شواهد به‌جای اعتماد‌به‌نفس** — تیک سبک و توضیح قاطع، اثبات نیستند.
- **استقلالِ ایجنت، به‌ازای هر کلاس کار** — داکیومنت و پرداخت نردبان‌های جدا با شواهد جدا دارند.
- **شکست پنهان نمی‌شود** — چک‌های اسکیت‌شده جدا گزارش می‌شوند.
