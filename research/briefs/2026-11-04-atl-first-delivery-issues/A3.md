## Outcome
A developer selects one real Azure Boards item and obtains a bounded, verifiable local task through either entry point. Reuse ATL's existing Azure integration; complete the user journey instead of adding another connector abstraction.

## Scope and existing foundation
runtime/lib/intake.mjs already has HTTPS Azure intake, environment-based authorization, iteration filtering, remote revision and same-revision deduplication. Existing Plan Studio/task execution supplies framing, approval boundaries and workspaces. Preserve these features and retain the Azure item URL/ID/revision through acceptance, execution and delivery.

## Control Plane
Use the existing issue-source preview/import and queue views. Show selected item, Ready-to-run result, acceptance checks, dependency or decision blockers and the local-delivery boundary. Implement the smallest missing connection between existing screens. Refuse stale plans when the source revision changes; do not reset user decisions on an unchanged import.

## Skills-only
Provide a documented path from an Azure URL/ID or a supplied Azure export to the same normalized task contract. Reuse/extract the minimal read-only adapter as a bundled portable helper when the host lacks an Azure connector; do not require the manager service. Use authorized environment credentials or host access. Mark a supplied export as a frozen snapshot, not a current live sync. Ambiguous acceptance becomes one explicit question/blocker rather than repeated planning loops.
